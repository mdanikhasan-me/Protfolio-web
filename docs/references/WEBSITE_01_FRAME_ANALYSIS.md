## Reading

Website 01 is not a continuous 3D homepage. It alternates between an immersive identity chamber and
conventional editorial pages. A dark bowed grid, fixed navigation, giant identity type, and a
transforming angular object maintain continuity while the content mode changes from spectacle to
evidence. This separation is why the experimental layer does not have to carry every reading task.

The table combines required fields as follows: each row records time/frame range, visible state,
moving and stable elements, likely input and implementation, motion purpose, performance
implications, transferable principle, and prohibited direct-copy elements. “Likely” remains a
hypothesis.

## Stable identity versus transforming layer

Stable:

- fixed small navigation and route affordances;
- bowed spatial grid and thin crosshair/guide marks;
- monochrome editorial typography;
- the concept of one central identity object;
- separation between content interface and experiential background.

Transforming:

- object silhouette, thickness, reflectivity, and image-bearing role;
- project media depth and scale;
- dark/bright material world;
- camera distance and perspective;
- section tempo and evidence type.

## Transition taxonomy

1. Object morph: folded ribbon to solid identity.
2. Object-to-media: project planes attach to or orbit the identity.
3. Physical aperture: a world plane opens into a bright chapter.
4. Typographic separator: giant type clears and reorients.
5. Media takeover: selected evidence becomes the environment.
6. Identity mask: the signature geometry clips project media.
7. Editorial handoff: immersive selection yields to conventional lists and pages.

## Performance hypotheses

- The bowed chamber, refractive object, bloom, chromatic separation, and several media planes imply
  a meaningful GPU and memory budget.
- The conventional News, Works, About, and case-study sections demonstrate that full WebGL does not
  need to remain active for every reading task.
- A responsible interpretation would pause or render-on-demand when the scene is not changing, cap
  device pixel ratio, lazy-load only the selected media, and provide a DOM/static equivalent.
- The recording proves appearance on one desktop capture, not frame rate, energy use, mobile
  support, keyboard access, reduced motion, or context-loss recovery.
