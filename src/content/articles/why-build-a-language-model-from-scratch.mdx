Calling a language model through an API takes a few lines of code. It's good for adding AI to a product, but it doesn't show me how a model works. I want to understand how text becomes tokens, how training data goes in, what has to be saved so training can continue, and how a saved checkpoint turns into an answer. The only way I know to learn that is to build it. So I'm building Salty Steak.

Salty Steak is more than a model. It has a tokenizer, data preparation, training, checkpoints, inference, and a desktop app around them. Building each part forces me to answer questions I'd otherwise skip. Does the tokenizer read the data the way I think it does? Does inference load the right checkpoint? Can the app show what's really going on without making the model look better than it is?

When I say “from scratch”, I mean I'm not calling someone else's model through an API. I still use libraries, and this isn't new research. It's an experiment. It isn't state-of-the-art or ready for real use, so I won't share a parameter count, benchmark or release date until I have real ones.

What I like most is that it stops feeling like one big mystery. I can test the tokenizer by itself. I can treat a checkpoint as just a file. That way of working helps with ordinary software too.
