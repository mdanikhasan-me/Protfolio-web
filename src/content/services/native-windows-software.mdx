## When a real desktop app is the better fit

A native Windows application makes sense when the software needs to live naturally on the desktop,
work with local operating-system features, store credentials safely, or provide an installed
experience without depending on a browser tab.

The choice still depends on the job. Before committing to native software, I look at distribution,
updates, integrations, offline behavior, security, and the people who will use it.

## The capability I can show

[SoctuKit](/work/soctukit/) is my clearest public example. It is built with C#, .NET 8, WinUI 3,
Windows App SDK, XAML, and MVVM. The product also includes tests, Windows Credential Manager
storage, and an Inno Setup installer.

That surrounding work matters. A useful desktop release needs clear application state, dependable
error feedback, safe local storage, installation, and a way to know whether an operation actually
succeeded.
